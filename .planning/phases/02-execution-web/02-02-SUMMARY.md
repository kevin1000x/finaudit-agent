## 二、与计划的三处偏离，逐条说明

### 1. T4 从 checkpoint 变成了已裁 —— 因为操作者把它交回来了

原计划 T4 是 `type: checkpoint`，产出「三条不一致 + 数字」交操作者。
2026-09-05 操作者原话：「剩下按你想法」⇒ 三条各裁一边，落成 `D-035`。

### 2. 🔴 计划（与 `EVAL_CASES` §5.4）挡在前面的那条理由**不成立**

两处都写着「本轮不新增第五层（那会动 `AC-08` 的 100% 归因覆盖率口径，属规格变更）」。

`AC-08` 逐字是「失败归因覆盖率 100%（每个失败都落到至少一层，不允许"未知"）」——
**它对层数不置一词**。真正会动 `AC-08` 的是**不**加层：
4 条真实 FAIL 里有 2 条（`Q-C3-003` 缺主体、`Q-C3-004` 多期间）被硬塞进口径层，
**那才让 100% 变成假的**。⇒ 加了第五层「意图层」。

### 3. `Attribution` 没有 `provisional` 字段

计划要求它「至少带 `layers` 与 `provisional`」。那是**落点未裁时**的必需品 ——
需要一个「临时落点 + 逐条登记进 `attribution_notes`」的通道。
`D-035` 裁完之后没有任何一条是临时的，**留一个永远为 `None` 的字段就是死抽象**。
⇒ 换成 `basis`：这次归因**是从哪个机读状态算出来的**。
没有它，复核者看到的只是一个层名加一句「相信我」。

## 三、三条硬产出

### 1. 判据全是机读的，`detail` 一个字都没碰

`EVAL_CASES` §5.3 是硬约束：靠上游措辞判出来的归因，在排版一变时**静默退回「正常」**。
判据只用三样：`RefusalCode`（封闭枚举）、`Answer.gate` 三态、`metric_id` / `metric_version`。
**语法树断言**锁住 `attribution.py` 里一次都没读过 `detail`（走 AST 不走子串 —— `RV-9`）。

### 2. 「本批零产出」与「结构上不可达」分开报

```
各层实际吃到的失败题数：
  意图层 2   检索层 0   口径层 2   计算层 0   表达层 0
  · 本批零产出（但结构上产得出来）：检索层、计算层
  ⚠️ **结构上不可达**：表达层 —— 当前实现里没有任何一条路能产出它。
```

`reachable_layers()` **从两张映射表机械算出**，不是手写的一句话
（有负控制：给 `RECONCILIATION_FAILED` 挂上表达层，它必须立刻变成可达）。

混成一句「零产出」，读的人会以为再多跑几批就有了 —— 而不可达的那个再跑一万批也不会有。
**表达层是 `L-25` 那种死抽象的形状，盯着它。**

### 3. `AC-08` 的负控制在**单 FAIL 套件**上做

计划点名这是最容易假绿的地方：在 frozen-01（4 道 FAIL）上做，
`main()` 本来就返回非零，**红的原因不是它声称在查的那件事**。
⇒ 用 `eval/testdata/sample-suite`（恰好 1 道 FAIL），并且退出码用 `3` 与 `1` 分开：
基线返回 1 → 把归因换成空 → 返回 3 且 stderr 点名 `S-C2-002`。
