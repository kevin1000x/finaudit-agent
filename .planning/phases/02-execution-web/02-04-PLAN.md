<context>

## 形态不是本计划选的，是两条在册决策定死的

见 `N-60`（四条事实都当场核过）：

- 浏览器里跑我们的答案路径 ⇒ 要把实现代码发出去 ⇒ `D-005` 明禁。
- 后端现算 ⇒ 服务端运行时 ⇒ `D-021` 的豁免边界一句话挡住，
  且反转触发条件明写要**连带重估 `D-005` 与 `D-014`**。
- ⇒ **只剩「静态回放一次真实运行」**。

**所以本计划不讨论架构选型。** 它讨论的是：怎么把一次真实运行导出成静态载荷，
以及怎么在页面上把「这是回放」说清楚。

## 🔴 这个项目最不该犯的错，恰好最容易在这一份里犯

把一次录好的运行演成现场计算 —— **「看起来对」与「可复核」的差别，
正是这个项目立项要反对的那件事**。演示如果自己就模糊了这条线，
后面所有关于证据链的主张都会被这一页拆掉。

⇒ 三条落到实现上的硬要求：

1. 页面显著位置写明：**这是一次真实运行的回放**，运行时间与运行哈希都在页面上。
2. 逐步展开的动画可以有，但文案是「**这一步当时做了什么**」，不是「正在推理」。
3. 输入框如果做成可输入的，**输入表里没有的问题必须明确说「这个演示只回放这 N 道」**，
   不许静默匹配到一个近似题目 —— 那是**静默选择**（`N-47` 的同一形状）。

## 载荷里没有的东西

`expected` / `rationale` / `attribution_hint` / 本次运行的 `PASS`/`FAIL` **一律不导出**。
理由和 `02-03` 的题包一样，但这里更强：演示是**对外**的，
把标准答案一起发出去等于把评测集也发了（`D-012` 冻结的意义在于「不拿模型结果反过来调答案」，
公开答案会让任何后续的 frozen-01 读数失去意义）。

⇒ `eval/demo.py` 复用 `eval/h2.py` 的 `leak_probes` / `no_leak_problems`，**不另写一套探针**。

</context>

<task id="1" name="载荷导出器（与 T0 无关，可先做）">

`eval/demo.py`：把 frozen-01 的一次真实运行导出成一份**可离线打开**的静态载荷。

每题一条记录：题面、`render_answer()` 的正文逐字、以及**回放用的分步序列**
（意图 → 闸门 → 口径 → 取数 → 计算 → 证据链，取自 `Answer` 与 `ExecutionRecord` 已有的字段，
**不新增任何字段**）。载荷顶部带这次运行的时间戳与 `execution_hash`。

不泄题由 `no_leak_problems` 守 —— **同一套探针，不另写**。
另加一条本计划特有的：载荷里不许出现 `PASS` / `FAIL`。

⚠️ 写盘走 LF（`eval/h2.py` 的 `_write()` 同款理由），并给载荷做 `SHA256SUMS` ——
演示站上那份和仓库里这份必须能对上，否则「可复核」在演示这一环就断了。

</task>
