## 🔴 三条不可协商的边界，写在最前面

1. **无状态**。判据是 `D-021` 豁免三那两句：
   ① 有没有进程在没人请求时运行？② 把存储清空会不会永久丢东西？
   任一为「是」即越界，**要用就得再修订 `D-021`**，不是在这份计划里顺手做掉。
   ⚠️ 「按请求触发、能缩到零的托管函数」满足它；「一台你要打补丁的常驻机器」不满足。
2. **不收用户的财务数据**。端点只接受一个问题字符串，**没有文件上传**（`D-010`）。
3. **服务端依赖闭包零 AGPL**。`D-014` 原本写的是一个假设 ——
   「Web 演示是网络服务；AGPL §13 要求向网络用户提供源码；而 `D-005` 主仓私有；
   二者不能同时成立」。**上线那一刻这不再是假设。**
   ⇒ 任何服务端新依赖先过 `scripts/verify_deps.py`，许可证一侧必须绿。
   （该门禁的**下载量**一侧因 `D-030` 跌破而红着（`D-036` 接受了）——**那不豁免许可证一侧**。）

## 🔴 覆盖面这件事，得先说实话

产品要「为任意公司现算」，而**我们并没有任意公司的数据**：
财务数值按 `NFR-04` / `D-013` 只能来自巨潮年报 PDF 原文，
而磁盘上真实跑通过的只有三家三年（茅台 2023 / 万华 2019 / 顺丰 2021，
且 `.gitignore` 明令 PDF 不进版本控制）。逐字段人工核对过的是**两家**。

**两条路，本计划选后者**：

| | 做法 | 为什么不 / 为什么是 |
|---|---|---|
| (a) | 请求时现下载并解析年报 PDF | 一次请求要下 + 解一份几百页的 PDF，托管函数的超时扛不住；而且**抽取质量在没核对过的公司上是未知的**，产品会开始输出没人验过的数 |
| (b) | **只对已核验的公司/年份作答，其余诚实拒答** | 覆盖面小，但每一个答案都站得住。**而且拒答本来就是这个系统的正常输出**（`D-003`）——「问了一家我们没数据的公司，它说清为什么没有」正是这个项目想展示的行为 |

⇒ **产品的第一版覆盖面 = 我们真的核验过的那些**，页面上写清楚。
把覆盖面装大，一次就把「可审计」这个卖点赔光。

<task id="1" name="把答案路径包成一个无状态端点（与托管商无关，先做）">

`src/service/api.py`：`POST /answer` 收 `{"question": "..."}`，
返回 `Answer.to_dict()` + `render_answer()` 的正文。**不新增任何业务逻辑** ——
它是 `answer_question` 的一层传输外壳。

- **无状态**：进程内不留任何跨请求的可变状态；`Registry` 与映射表是只读的，启动时加载。
- **没有文件上传**，请求体只有一个字符串（`D-010`）。
- **每一步失败都落成拒答，不抛 500**（`D-022` 的同一条纪律延到 HTTP 边界）。
- 依赖能少则少；新增的每一个都过 `verify_deps.py`。

`tests/test_service.py` 至少守住：
- 端点在**任何**输入下都不返回 5xx（含空串、超长串、非中文、注入形状的串）
- 响应里出现 `render_answer()` 的正文**逐字**（不另写一版渲染）
- **无状态断言**：同一个问题连问两次，两次响应逐字节相同；
  且模块里没有模块级可变容器（语法树查，同 `test_agent_boundary.py` 的做法）

</task>
