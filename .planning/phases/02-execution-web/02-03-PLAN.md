## 🔴 三条这次实验做出来之后**必须跟着结论一起转述**的限定

这三条不是免责声明，是**这次读数能读到什么程度**的边界。写在计划里，
是为了它们在出数那天已经存在，而不是事后补。

**限定 1 —— 15 题里只有 5 题是「一个数」，另外 10 题是拒答。**
（实跑：`Q-C1-001/002/004/005/006` 出数；其余十道全是拒答。）
⇒ 复核者在 10/15 上判的是**「这次拒答对不对」**，不是「这个数对不对」。

**限定 2 —— 🔴 四道错题**全部**是拒答形态。**
`Q-C1-003` 拒答理由码给错；`Q-C3-003/004/005` 该作答却拒答了。
而 §4.2 三档的**判别力主要来自错题子集**（一律判「对」的复核者在正确答案上照样拿高分）。
⇒ **这次 H2 实际测的是「证据链能不能让人抓出一次错误的拒答」**，
**不是**「能不能让人抓出一个错误的数字」。后者在 frozen-01 上**零样本**。
转述时不许把前者说成后者。

**限定 3 —— 复核者不独立于本项目。**
`EVAL_CASES` §4.1 只要求「有审计或财务背景」，没要求「没读过这个仓库」。
本项目唯一可用的复核者是操作者本人，他见过题集。
⇒ 与 `POC-01` 同款：**通过只能读作「未被证伪」**（`PROGRESS` 对 POC-01 的措辞逐字沿用）。

## 一个看起来像 bug、其实是信号的东西，先写下来免得被「修掉」

`Q-C3-003` 的系统输出是：**拒答，理由「题面里没有主体（六位股票代码）」**——
这个理由**本身是成立的**（题面确实只给了公司简称）。
而标准答案说它应该答出 `0.55` ⇒ 本次运行判 `FAIL`。

于是完全可能出现：复核者读完证据链认为「这次拒答有道理」，判**对**，
而标准答案说**错** ⇒ 计入不一致。

**这不是判分口径的毛病，这正是 H2 要测的那件事**：证据链把一个错误的结果
讲得足够有道理，以致复核者认可了它。
⇒ **不许为此调判分、改题包措辞、或给复核者补充说明。**

## 复核者看什么

**就是 `render_answer()` 的输出，逐字**。`D-032` 定的就是这条：
「`AC-06` 的复核者限时 5 分钟仅凭证据链判对错 —— **他读的就是这个**」。
本计划**不另写一版给复核者的排版**；另写一版就等于测了一个不会上线的东西。

⚠️ §4.1 第 2 步写着「看不到**模型的自然语言解释**」。
**我们的系统臂根本不产出模型散文**（意图解析之后全程确定性，且评测不注入模型）。
⇒ 这一条在这里是**平凡满足**的。如实记着，别写成「我们特意屏蔽了它」。

<task id="1" name="题包生成器，且不泄题这件事由测试守">

`eval/h2.py`：从**一次已完成的运行报告**（`eval/runs/*.json`）+ 冻结题面，
生成复核者拿到的那一份。**不重跑** —— 题包必须和某一次具体运行的 `PASS/FAIL` 对齐，
重跑会让「复核者看的那次」和「拿来比对的那次」错位。

- 匿名号 `H2-01 … H2-15`，用**记录在案的种子**打乱定序
  （不打乱的话 `Q-C2-*` 连着四道全是拒答，读到第三道就能猜出这一段的形状）
- 每题正文 = `render_answer(answer, defn, flag_descriptions)`，逐字
- 对照表 `keymap.json` 单独一份文件，**不进题包**

**不泄题由测试逐条守**，不靠人记：
- 题面 YAML 里 `expected` / `rationale` / `attribution_hint` / `must_not_resolve_to` /
  `judging` 各自的**取值字符串**，一个都不许出现在题包里
- 运行报告里那题的 `status`（`PASS`/`FAIL`）与 `attribution` 各层名，不许出现
- ⚠️ **反空转**：这条测试必须证明它真的在查（构造一份把标准答案塞进 `detail` 的假答案，看它红）

</task>

<task id="2" name="空白答卷 + 回填后算数">

- `answer-sheet.yaml`：15 条，每条 `verdict: ` 留空，取值域 `对 / 错 / 无法判断`，
  另有 `note:` 供复核者写一句为什么。**答卷里不含匿名号以外的任何信息**。
- `score()`：读回填后的答卷 + 运行报告 + `keymap`，算：
  - **一致率** = 复核者判定与本次运行 `PASS/FAIL` 相符的题数 / `N`
    （复核者判「对」↔ 运行 `PASS`；判「错」↔ 运行 `FAIL`；判「无法判断」**不计入一致**）
  - **无法判断率** = 判「无法判断」的题数 / `N`（§4.3 的反向检验，>20% 即使一致率达标也要补齐重测）
  - **错题子集上的原始计数** `x / W` —— §4.2 附注强制要求，不许只给百分比
- ⚠️ **答卷未填完就拒绝算数**（fail-closed）：留空的题**不许**当成「无法判断」。
  「没填」和「填了无法判断」是两件事，混同会让 §4.3 那道反向检验失真。

</task>

<task id="3" name="判定门 + 三条强制标注，缺一条就不出结论">

`score()` 的输出里，下面五项**缺一项即拒绝给结论**（返回非零 + 点名缺哪一项）：

1. `sampling: 普查`（不是「随机抽样」）—— §4.1.1 第 1 条
2. `w_ge_5_satisfied: false` + `w: 4` —— §4.1.1 第 2 条
3. `resolution_floor_on_wrong: 1/4 = 25%` —— §4.1.1 第 3 条
4. 落在 `60%–80%` 时必须同时给出 `x / W` —— §4.2 附注
5. 上面 `<context>` 里那三条限定的**指针**（不复述全文，指到本计划）

**三个数值门槛一个不动**：`≥80%` 通过 / `60–80%` 部分成立 / `<60%` 停止；`无法判断 ≤20%`。

</task>
