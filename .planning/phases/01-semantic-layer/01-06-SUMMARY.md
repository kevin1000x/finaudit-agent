## 三次同型错误，以及从中固化下来的规则

写 19 份定义的过程中，我**三次**给 flag 编造了求不出值的 trigger，三次都自己发现并改掉：

| 位置 | 我写的 | 为什么是错的 |
|---|---|---|
| `gross_profit_margin` | `unit_scale_mismatch` ← `营业收入 == 0 and 营业成本 != 0` | 那不是单位不一致，纯属拿别的条件凑 |
| `current_ratio` | `parent_only_scope` ← `流动资产 < 0` | 流动资产为负与母公司口径毫无关系 |
| `period_expense_ratio` | `basis_version_mismatch` ← `standard_basis.version != ...` | 计划里就这么写的，而它正是 OQ-04 移除的写法 |

三次的共同点：**报表数据里根本没有承载该概念的字段**，于是拿手边能求值的东西凑一个。
凑出来的是一条**永远不会正确触发的假规则**——与 POC-01 发现的「`common_pitfalls` 是散文」
同型，只是换到了 trigger 上。

固化下来的规则：**只有当存在真实字段能诚实触发时，才声明这个 flag。**
没有字段就不声明，把风险如实写成 `advisory_only` 并注明「本定义无法对此设可求值规则」。
`gross_profit_margin` 里那条关于计量单位的陷阱就是这么处理的。

这条规则值得写进 01-08 的裁决材料：它解释了为什么 4 个 flag 零引用，
也解释了为什么 `advisory_only` 占比不应该被压到 0——**有些风险确实没有机械后果，
硬给它一个才是造假。**

## 各批次要点

### 01-04 利润表与盈利能力（6 份）

`roe_weighted_average` 是最能体现立论的一份。加权平均净资产收益率的加权涉及净资产增减变动的
**月份权数**，年度报表不足以复算。定义立场是只取披露值、**禁止倒推**——
不得用归母净利润除以期末或平均净资产，那算出来的是全面摊薄或简单平均，不是同一个数。
未披露即拒答。这是 spec R3「禁止倒推时缺失即拒答」的真实实例，
也是通用 Agent 最容易「用手头的数算一个出来」的地方。

ROA 分子**含**少数股东损益，与归母类指标相反，理由是与分母（全部资产）配比。
两处相反的选择各自配了 `enforced_by` 的陷阱说明理由。

### 01-05 资产负债表与偿债（6 份）

spec R3 的两个分支现各有真实实例：`false` 由 tracer 与资产负债率承载，
`true` 由**有息负债率**承载。后者在合并资产负债表上没有单一列报行项，分项加总是唯一构造方式
而非缺失时的权宜，因此 `derivation.note` **穷举**了允许加总的六项并列明不得纳入什么——
一个「允许由分项推算」而不说清哪些分项的定义，等于没有定义。

两组对照各自证明一条 Requirement 真的成立：存货缺失拒答 / 为 0 正常算；
有息负债六个分项各自缺失都拒答（6 条参数化）/ 全为 0 正常算。

`net_working_capital` 处理了「负值 ≠ 未定义」：流动负债超过流动资产时不拒答。
「负值即异常」是这里最常见的实现错误，它把提问者最想知道的信息变成拒答。

### 01-06 现金流与周转（7 份）

`free_cash_flow` 承认**自由现金流没有会计准则定义**，`standard_basis` 只支撑两个分项各自的
列报依据，不支撑「相减」这个组合。这正是项目立论的展示物：
`anthropics/financial-services`（34.3k★）写 `FCF = Operating CF - CapEx` 恰恰没说这句，
因为它的口径被外包给了 FactSet / S&P；A 股没有这一层。

净现比与归母净利率**立场相反**（前者分母 ≤ 0 拒答，后者分子为负不拒答），
理由写进定义并有测试断言该理由可查——否则复核者会认为两处不一致。

三份周转天数的 365 基数与期末立场**逐份显式**，有参数化测试断言 `derivation.note`
里确实出现 `365` 与「期末」，不靠继承批次约定。

## `standard_basis` 中未精确到条号的条目（计划要求列出）

共 28 条使用「全文」、章名或附件名而非具体条号，分三类原因：

1. **准则整体即为依据**（「全文」，11 条）：如《企业会计准则第 14 号——收入》之于营业收入的
   确认与列报、《第 1 号——存货》之于存货。这类准则的适用不局限于某一条。
2. **章级定位已足够精确**（章名，10 条）：如《第 33 号——合并财务报表》第五章（少数股东权益的列报）、
   《第 31 号——现金流量表》第二章（经营活动现金流量的分类与列报）。
3. **格式类文件本身按附件组织**（附件名，7 条）：财会〔2018〕15 号的规范性内容在附件的报表格式
   与编制说明里，没有条号可引。

**这是当前的诚实状态，不是达标状态。** AC-05 要求准则引用可定位到具体条号，
Phase 3 的 L2 准则检索层落地后应逐条收窄。在此之前，
用「全文」而不编造一个看似精确的条号，是两害相权取其轻。

## 三件事的裁决（2026-08-15，操作者）

1. **4 个零引用的 definition 域 flag** —— **留着，等有字段承载时再用。**
   它们描述的风险真实存在（母公司口径、未经审计、单位不一致、币种不一致），
   缺的是数据侧承载字段而不是概念本身。删掉等于承认这些风险不存在，
   而 Phase 2 引入 PDF 抽取后 `unaudited` 与 `parent_only_scope` 都可能拿到真实字段。
   **约束**：在拿到字段之前，任何定义都不得为它们编造 trigger（见上方「三次同型错误」）。
2. **`standard_basis` 的条号精度** —— **认可当前状态，Phase 3 的 L2 落地后再收窄。**
   现在编一个看似精确的条号比诚实写「全文」更糟。
3. **OQ-04 的根因** —— Phase 2 必办，判据见 `open-questions.md`。
