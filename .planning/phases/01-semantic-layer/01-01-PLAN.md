## Q1 — 受限布尔 DSL 的具体语法：**单行字符串表达式 + 自研递归下降解析器**

**决定**：条件写成单行字符串（如 `notes.restatement_flag == true`），
由 `src/semantic_layer/dsl.py` 里自研的词法器 + 递归下降解析器解析成本项目自己的受限语法树。

| 方案 | 结论 |
|---|---|
| A. YAML 嵌套结构表示表达式 | **否决**。§5.1 的示例本身写的就是单行字符串（`trigger: notes.restatement_flag == true`、`expr: is_missing(...)`）；改成嵌套结构等于先改权威文档才能动工。且一条谓词摊成 5 行 YAML，复核者读它比重算还慢——正是 D-003 要避免的失效。 |
| B. 单行字符串 + Python `ast.parse` 白名单校验 | **否决，且有硬证据**。字段前缀 `is.`（合并利润表）是 Python 关键字，`ast.parse("is.net_profit_attributable_to_parent - notes.x", mode="eval")` 抛 `SyntaxError: invalid syntax`（2026-08-15 于 Python 3.14 实测）。而 `is.` 前缀同时出现在 `PROJECT_SPEC.md` §5.1 的示例公式与 `poc-01/field_inventory.md` 里，改前缀就是改权威文档的既有示例。 |
| C. 单行字符串 + 自研递归下降解析器 | **采纳** |

理由（对齐 design.md D1 的两条）：
1. **可静态检查**：语法树节点类型是本项目自己定义的 7 种，天然封闭。L3 `pre_execute` 检查的是**我们的**树，不是 Python 的树，检查面积小到可穷举。
2. **可被人读懂**：复核者看到的就是 `is_missing(notes.nonrecurring_pl_net_attributable_to_parent)` 一行。
3. **不引入任意代码执行**：不调用 Python 的内置求值/编译入口，这一点由测试用负向 grep 锁死，不靠承诺。

**能力边界（不得扩张）**：字段引用、比较运算（6 个）、逻辑 and/or/not、`is_missing()`。
无其他函数调用、无循环、无赋值、无算术。写不出来的约束**记为 Open Question，不许就地扩语法**
（design.md §Risks 已明确：扩语法会一路滑回通用表达式）。

## Q2 — 全局 flag 词表的物理位置：**`metrics/_flags.yaml`**

**决定**：独立的机器可读文件 `metrics/_flags.yaml`，与 20 份定义同目录。

理由：
1. R4 要求「flag 必须来自受控词表」由**校验器**执行。词表若嵌在 `PROJECT_SPEC.md` 的 markdown 表格里，
   校验器就得从人读文档里正则抠数据——这正是本次 schema 扩展要消灭的「散文冒充规则」，换个方向重演。
2. **不构成第三份权威文档（D-009）**，靠**范围**保证而非靠位置：`_flags.yaml` 只承载
   flag 名 → {描述, scope, 是否影响可比性, 引入依据} 的枚举，不定义任何字段语义、不写任何验收标准、
   不作任何决策。它与 `openspec/specs/**/spec.md` 是同一种关系：规格的可测投影，冲突时以
   `PROJECT_SPEC.md` 为准。这条从属关系在 01-02 写进 §5.1。
3. D-005 允许 Phase 1 结束时把 `metrics/` + 问题集单独开源为姊妹仓库。词表放在 `metrics/` 里，
   姊妹仓自带词表；放在 `PROJECT_SPEC.md` 里则要么开源整份规格，要么开源一批引用空词表的定义。

**§5.1 的前置条件已满足**：§5.1 要求「有 5 个以上真实 flag 后再定位置」。Task 1 一次性建立 10 个
flag（覆盖全部 20 个指标的已知需要），因此定位置的前提在本任务结束时成立，01-02 随即走 OpenSpec 记录。

**可逆性**：`costly`。20 份定义引用的是 flag **名**不是路径，迁移成本 = 移一个文件 + 改一个路径常量 +
改 §5.1 一行。不设 `checkpoint:decision`。
