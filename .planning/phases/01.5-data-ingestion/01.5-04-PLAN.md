## API 覆盖决定 —— AKShare（本计划的外部 API 面，显式枚举）

**用到的调用面（三个，全部只读、无鉴权）**

| 调用 | 用途 |
|---|---|
| `ak.stock_financial_report_sina(stock="sh600519", symbol="资产负债表")` | 对照 `bs.*` 字段 |
| `ak.stock_financial_report_sina(stock="sh600519", symbol="利润表")` | 对照 `is.*` 字段 |
| `ak.stock_financial_report_sina(stock="sh600519", symbol="现金流量表")` | 对照 `cfs.*` 字段 |

**明确不做的 AKShare 面**（写下来，而不是「跑通一个就算集成完了」）：

- **不用 AKShare 的加工指标接口**（`stock_financial_analysis_indicator` 一类）。D-013 已把二手源降级为对照，
  用它的**加工指标**去对照我们从原文算出的指标，比的是两套口径而不是两套取数，结论不可解释。
  只对照**报表原始科目**。
- **不用 AKShare 做数据源兜底**。PDF 抽不到时返回 `Refusal(UNAVAILABLE)`，不改用 AKShare 的值——
  那正是「降级成功」，D-003 明令不接受。
- **不对照 `notes.*` 与 `kpi.*`**：AKShare 的三张报表接口里没有附注与「主要会计数据和财务指标」章节，
  强行对照只会得到一堆「对照源无此项」。这四个字段在本阶段只有 PDF 一个来源，如实记录。
- **不做多期批量拉取**：接口一次返回 103 期，本阶段只取目标年度那一期。
- **不做行情、不做资金流、不做公告类接口**——与财务数值无关。
- **不缓存到 Supabase 或任何外部服务**（cninfo 那套缓存不复用，D-004 的资产隔离与本项目「零外部状态」都指向同一结论）。
