<objective>
本阶段的 tracer 切片：把一条真实路径从巨潮的 HTTP 端点一路打通到一个算出来的真实数值，
中间每一层都是生产质量，不是原型。

一条路径 = 贵州茅台 2023 年报 → 合并资产负债表 → 三个 bs 字段 → 带完整出处的抽取记录 →
批次级勾稽闸门 → 封闭算术解析器 → `debt_to_asset_ratio` 的真实数值 → 证据链 JSON。

**为什么三个字段而不是一个**：`debt_to_asset_ratio = bs.total_liabilities / bs.total_assets`
是唯一一个「两个字段、同一张表、单次除法」的指标，而补上 `bs.total_equity` 恰好凑齐
D-018 的勾稽恒等式。三个字段是让这条切片同时穿过「计算」与「闸门」两层的最小集合。
且 `bs.total_equity` 正是 A-4 实测中被章节小标题「所有者权益（或股东权益）：」骗过的那个字段
——把最难的那条真实失效模式放进 tracer，而不是留到横向扩展时再撞。

**与 ROADMAP「wave 0 是探测，不是写抽取器」的关系**：那条约束防的是
「在 14 个字段可行性未知时就把整个抽取器写完」。本计划只走 `bs.*` 这条

无处可跑。零实测字段的探测在 `01.5-02-PLAN.md`，**排在任何横向扩展之前**。

后续五份计划都显著更小。

## API 覆盖决定（本阶段确实集成外部 API，故显式枚举）

**巨潮资讯网 —— 用到的端点（共三个，全部无鉴权、无 cookies，CONTEXT §3.4 实测）**

| 端点 | 方法 | 用途 |
|---|---|---|
| `www.cninfo.com.cn/new/data/szse_stock.json` | GET | 股票代码 → `orgId` |
| `www.cninfo.com.cn/new/hisAnnouncement/query` | POST | 按 `category_ndbg_szsh` 查年报公告列表，取 `adjunctUrl` |
| `static.cninfo.com.cn/{adjunctUrl}` | GET | 下载 PDF |

**明确不做的巨潮接口面**（列出来，而不是「第一个用例跑通就算集成完了」）：

- 公告全文检索接口（`/new/fulltextSearch/*`）——本阶段按代码+年度精确取年报，不做全文检索
- 季报 / 半年报 / 摘要 / 英文版类目——SC 只要求年度报告全文，标题筛选主动排除
- 互动易、公司公告推送、行情类接口——与财务数值无关
- 分页遍历全市场——CONTEXT §5 明确「先单公司单年」，`pageSize` 取够一年即可，不做全量抓取
- 任何写操作 / 订阅 / 登录态——巨潮公开页面不需要，也不允许本项目持有任何账号

**AKShare**：本计划**完全不接触**。它的调用面与「明确不做」在 `01.5-04-PLAN.md` 的同名章节列出。
