## Overview

从一条可复现的实证结论出发，先把最难被复制的语义层做实，再用可信执行层把「答案」变成「可复核的答案」，最后补知识层与评测闭环。每一阶段单独可讲、单独有价值，不依赖上层完成。最危险的假设 H1（口径可判定性）已由 POC-01 验证为**未被证伪**（`docs/agent/poc-01/`）。

### Phase 1.5: 数据接入层 data-ingestion
> **INSERTED 2026-08-15**（这个标记原本写在标题里，会污染 GSD 生成的 slug，移到此处）

**Goal**: 把年报 PDF 变成语义层能消费的结构化字段，并让指标真的算得出数值。
**Depends on**: Phase 1（没有口径定义，抽出来的字段不知道该叫什么）

**为什么插进来**：Phase 1 结束时 20 份口径定义全部合规，但**没有任何真实数据可喂**，
且 `formula` 只是字符串描述、受限 DSL 不含算术，**系统算不出任何一个数**。
Phase 2 的 H2 复核实验要求复核者看着**真实数字与证据链**判断——没有真数据，
那个实验做不了，Phase 2 立不住。这不是新增范围，是补一段此前没写出来的必要前置。

**Success Criteria** (what must be TRUE):
  1. 能从巨潮下载指定公司指定年度的年报 PDF，并定位三张合并报表所在页
  2. 20 份定义所需的 30 个字段中，≥ 24 个能从 PDF 抽出并映射到字段 id；
     每个映射有版本化的映射表条目，**不允许模糊匹配**
     **计数口径（2026-08-21 写死，此前含糊）**：「能抽出」= **取到的值经逐个人工核对正确**，
     **不是「标签命中」**。这条与 SC-8 是同一件事的两面——SC-8 只说了验收原则，
     而 SC-2 的「≥24」是个计数，计数口径不写死就会默认退化成命中数。
     A-4 已有真实反例：`bs.total_equity` 匹配到章节小标题「所有者权益（或股东权益）：」，
     数值为空，**报表上算命中，实际取错行**。
     **已实测覆盖 16/30**（bs 15 + `notes.business_combination_type` 1）；
     **is 8 / cfs 2 / notes 3 / kpi 1 共 14 个字段零实测**，而 ≥24 意味着最多只能失手 6 个
  3. **区分「行在但格子空 = 0」与「整行不存在 = 缺失」**，各有真实样本驱动的回归用例
  4. 抽取产物带出处：PDF 的 SHA-256 + 巨潮源 URL + 页码 + 计量单位与币种
  5. 数值执行层能对至少 5 个指标算出真实数值，并与 AKShare 交叉校验；
     不一致时置 `source_disagreement` 标记而不是静默选一个
  6. 默认**不保留 PDF**（抽完即删），`--keep-pdf` 是显式开关
  7. **勾稽校验是阻断式的**（新增 2026-08-16，台账 N-13）：至少实现
     「资产总计 = 负债合计 + 所有者权益合计」，不通过即拒答而非记日志；
     有一条真实年报驱动的通过用例与一条构造的失败用例。
     **理由**：cninfo 完全没有这一层（读完 `pipeline.py` / `metrics.py` / `utils.py` /
     `downloader.py` / 6 个测试文件，无任何会计恒等式校验），这层要从零建
  8. **抽取器的验收看「取到的值」，不看「命中数」**（新增 2026-08-16，台账 A-4）：
     命中数会被标签前缀匹配骗过——实测中 `bs.total_equity` 曾匹配到章节小标题
     「所有者权益（或股东权益）：」而数值为空，报表上是「命中」，实际取错了行

**明确不做**：不做 OCR 兜底（先只处理文本型 PDF）；不做全市场批量（先单公司单年）；
不引入向量检索（那是 Phase 3）。

**已验证的技术起点**（2026-08-16 用 **pdfplumber 单库**实测，台账 A-4 判据达成）：

下载三步链路不需要 cookies。抽取侧在茅台 2023（143 页）上实测：
**8 张报表标题全部定位、合并与母公司干净分离；15 个 `bs.*` 字段命中 15/15**
（行在有值 11 ｜ 行在格子空 4 ｜ 整行不存在 0）；顺带跑通一次勾稽校验
（资产总计 = 负债合计 + 所有者权益合计，**差额 0.00**）。
D-014 的反转条件未触发，**不需要试 pypdfium2**。

**三条必须设计进去的失效模式**（都是实测撞出来的，不是假想；第一版探测因此直接零命中）：
1. **表标题印在上一页的页脚位置**，数据从下一页开始 ⇒
   任何「标题与锚点必须同页」的规则必然落空。
2. **合并表与母公司表的边界在页内**（p61 上半是合并表尾巴，下半是母公司表标题）⇒
   按「页」定位必然混表——这正是 D-013 记录的 cninfo「最后一个匹配的表静默胜出」的成因。
   **正解**：表标题当作带 y 坐标的锚点，区间 = [本标题, 下一标题)，跨页且可页内切分。
3. **行项目标签折行，且数值行夹在两个标签片段之间**：
   `归属于母公司所有者权益` / `215,668,571,607.43 …` / `（或股东权益）合计`。
   缝合规则：`标签行 → 纯数值行 → 标签行` 三行属同一行项目。

附注编号列的处理：数值正则要求**两位小数**即可排除附注号——
但这是**单样本结论**，若遇到列出整数金额的报表会失效，按列位置剔除更稳妥。

### Phase 2: 可信执行层与 Web 演示
**Goal**: 跑通一次完整问答，产出能让人独立复核的证据链，验证 H2；并在 Web 上可演示。
**Depends on**: Phase 1（没有语义层，闸门无从校验）+ Phase 1.5（没有真数据，H2 实验做不了）
**Success Criteria** (what must be TRUE):
  1. 每条回答产出完整证据链，字段齐全率 100%（AC-05）
  2. 复核实验中一位有审计背景的复核者仅凭证据链、限时 5 分钟，与标准答案一致率 ≥ 80%（AC-06，H2 判定门）
  3. 复核者判为「无法判断」的题目占比 ≤ 20%
  4. 每个失败都归因到检索/口径/计算/表达至少一层，覆盖率 100%（AC-08）
  5. `pre_execute` 拒绝全部已知危险样本（AC-09）
  6. **口径闸门是单调的前置钩子**：不存在任何配置或插件路径能让 LLM 绕过它
     直接作答；被拒答的请求同样留下完整日志记录
  7. Web 端能完成一次「提问 → 流式推理 → 带证据链的答案卡」，可分享链接
**Plans**: TBD

**停止条件**：若复核一致率 < 60% → **停止，回到 ARCHITECT 重设计证据链，不得进入 Phase 3**。

**交付形态（2026-08-15 变更）**：原写「TUI」，改为 **Web 为主 + 本地 GUI 减量**。
理由：D-006 说过「TUI 是交付形式不是卖点」——既然形式无所谓，就选招聘方点开链接就能看的那个。
Web 在既有的 `../cninfo-analyzer-web` 上**增量加页面**，复用其 SSE、刷新恢复与部署链路。
本地 GUI 以自用适配为主，**不占阶段验收**。

**必须先切干净内核与壳**：语义层 + 执行层 + 证据链为内核，Web 与 GUI 各是薄壳
（照 deepseek-harness 的 `web` / `headless` 两个 profile 共用 `dsh-base`）。
不先切干净，两个界面就是做两遍。边界画在 `ARCHITECTURE.md` 里。

**明确不做**：不做主题美化、不做插件体系、不做快捷键（D-006）。

## 依赖与顺序约束

```text
Phase 0    ──独立，可随时做

Phase 1.5  ──依赖 Phase 1（没有口径定义，抽出的字段不知道叫什么）
```

**Phase 0 与 Phase 1.5 共用同一条下载与定位链路**——审计报告正文就在年报 PDF 里，
位置紧邻合并资产负债表（茅台 2023 是 p57）。两者可以合并做，也可以 Phase 1.5 先建
下载与定位能力、Phase 0 复用。

现在的判断依据是注意力而非小时数——两个阶段验证的东西不同（实证结论 vs 语义层），切换成本真实存在。
