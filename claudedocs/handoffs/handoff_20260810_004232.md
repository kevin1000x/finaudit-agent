- **「代码里没有」不等于「实际没有」——同一天犯了三次**：① 判 cninfo 只有 roa/ocf 两字段（错，那是 AKShare 路径的窄化选择，不是能力上限）；② 判 cninfo 没用 HuggingFace（错，**后端跑在哪仓库里根本不写**，生产链路是 Pages Function → 具名 Cloudflare Tunnel → `API_BASE` 这个 Pages secret）；③ 判「报表没有承载计量单位的字段」（错，年报页头就印着「单位:元 币种:人民币」）。**`references/` 这个文件夹就是为此而建的**：每份标注读到什么程度，未读部分不许出现在结论里。
- **给 flag 编造求不出值的 trigger——也犯了三次**：`unit_scale_mismatch ← 收入为零`、`parent_only_scope ← 流动资产为负`、`basis_version_mismatch ← 计划原文那条`。共同点是**报表里没有承载该概念的字段，于是拿手边能求值的东西凑一个**。凑出来的是永远不会正确触发的假规则——与 POC-01 的「`common_pitfalls` 是散文」同型，只是换到了 trigger 上。**已固化规则：只有真实字段能诚实触发时才声明 flag。**
- **R4 与 R8 曾直接打架**：R4 禁止定义文件声明 system 域标记，而 R8 的实现只认定义内声明的标记 ⇒ 任何「跨期不可比」类陷阱在构造上都无法满足 R8。这是 01-02 引入 R4 新约束时带出来的，此前没有 system 域标记被 `enforced_by` 引用过所以没暴露。
- **01-02 的反向核对漏了一维**：只做了「规格 ↔ 实现」，没做「规格 ↔ 下游消费者」。规格是给 19 份尚未写出的定义用的，只跟已有实现对齐等于只验证了「规格描述了现在有什么」。后果是 `kpi` 与 `derivation` 两个枚举项漏抄，wave 3 开写时才炸出来。
- **PDF 取数的真正难点是坐标不是库**：PyMuPDF `get_text()` 把表格拆成逐单元格一行，标签与数字不在同一行。必须取 `get_text("words")` 按 y 坐标聚簇重组行。40 行代码，茅台 2023 资产负债表抓到 9/12。
- **空格子 ≠ 缺失（实证）**：茅台 2023 的短期借款/长期借款/应付债券**行项目印在报表上但值的格子是空的**——公司声明该项为零。当前 `interest_bearing_debt_ratio` 会据此拒答，而正确答案是接近 0。规则应为「行在格子空 = 0，整行不存在 = 缺失」，住在抽取层。
- **巨潮年报下载不需要 cookies**（实跑验证）：`szse_stock.json` 取 orgId → POST `/new/hisAnnouncement/query` → `static.cninfo.com.cn/{adjunctUrl}`。标题筛选必须排除摘要/英文版。
- **deepseek-harness 给出了语义层闸门的正确形状**：`agent/pre-step` 可 **reject**，`tools/pre-execute` 是**瀑布**（listener 不调 `next()` 即阻断）。所以口径闸门应是**前置钩子**而非**可选工具**——结构上无法绕过。这解决了 hello-agents「万物皆 Tool」带来的致命问题：若口径查询只是可调工具，LLM 就可以不调。

```yaml
version: 2
grain: {entity: stock_code, period: fiscal_year, period_type: annual}
source_fields:
  - id: is.net_profit_attributable_to_parent
    sign_convention: 收益记正_损失记负     # 参与加减者必填，C4 的落点
    missing_representation: null          # 缺失与零必须可区分，R6 的落点
derivation: {allow_from_components: false, note: 禁止由分项倒推}   # 必填，二选一
standard_basis:
  - {name: ..., issuer: ..., article: ..., version: "2023"}      # 四键缺一即 R5 不合规
flags:
  - {name: restated, trigger: notes.restatement_flag == true}    # 只能引用词表的 definition 域
  # scope: system 的标记（basis_version_mismatch / metric_version_mismatch /
  # source_disagreement）**不在定义文件内声明**——只有比较两期才判定得出（OQ-04）
undefined_conditions:
  - {expr: is_missing(notes.x), reason: ...}                     # 必须可求值
common_pitfalls:
  - {text: ..., enforced_by: flags.restated}     # 元规则：二选一
  - {text: ..., advisory_only: true}             # 皆无即不合规
```

**元规则（BREAKING，本次扩展的核心）**：每条 `common_pitfalls` 必须要么有 `enforced_by` 指向可求值规则，要么显式标 `advisory_only: true`。二者皆无 ⇒ 定义不合规。监控：Phase 1 结束时 `advisory_only` 占比 **> 50% 视为元规则失效**，须重新设计。
