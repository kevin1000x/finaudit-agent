## Purpose

定义一份财务指标口径定义必须满足的结构契约，使「这个口径对不对」可以被机械判定而不是靠人阅读散文后凭印象判断。契约的核心立场：凡是会影响取数、计算方向或可比性的约束，必须以可求值的形式存在；仅供人阅读的提示必须被显式标注，不得冒充规则。

## ADDED Requirements

### Requirement: 口径定义必须声明数据粒度

一份口径定义 MUST 声明其 `grain`，包含实体维度与期间维度。缺少 `grain` 时，`formula` 无法定位到唯一一行数据，该定义 MUST 被判定为不合规。

#### Scenario: 缺少粒度声明

- **WHEN** 一份口径定义提供了 `source_fields` 与 `formula`，但未声明 `grain`
- **THEN** 该定义被判定为不合规，且不合规理由可机读

#### Scenario: 粒度完整时可定位

- **WHEN** 一份口径定义声明了实体标识与报告期（含会计年度与报告期类型）
- **THEN** 给定一个实体与一个报告期，`formula` 引用的每个字段都能解析到唯一取值

### Requirement: 口径定义必须声明取数字段的符号约定

对参与加减运算的每个 `source_fields` 条目，定义 MUST 声明其符号约定（例如「收益记正、损失记负」或「按绝对值列报」）。

#### Scenario: 符号约定缺失

- **WHEN** 一份口径定义的公式含减法，但未对被减项声明符号约定
- **THEN** 该定义被判定为不合规

#### Scenario: 符号约定错误不得静默通过

- **WHEN** 数据源实际采用的符号约定与定义声明的不一致
- **THEN** 该情况 MUST 被标记为口径层失败，而不是产出一个方向相反但看起来正常的数值

### Requirement: 口径定义必须显式声明是否允许分项倒推

当一个字段在数据源中缺失、但可由其他已披露分项推算得出时，定义 MUST 显式声明允许倒推或禁止倒推，二者必选其一，不得留空。

#### Scenario: 未声明倒推策略

- **WHEN** 一份口径定义引用的合计字段存在可由分项推算的路径，但定义未声明倒推策略
- **THEN** 该定义被判定为不合规

#### Scenario: 禁止倒推时缺失即拒答

- **WHEN** 定义声明禁止倒推，且所引用字段在数据源中缺失
- **THEN** 系统拒绝作答，即使分项字段齐全

### Requirement: 标记必须来自受控词表并具备可求值的触发条件

定义中使用的每个标记（flag）MUST 来自一个受控词表，且 MUST 附带可求值的触发条件。触发条件 MUST 只引用已声明的字段。

#### Scenario: 使用词表外的标记

- **WHEN** 一份口径定义使用了受控词表未收录的标记名
- **THEN** 该定义被判定为不合规

#### Scenario: 标记无触发条件

- **WHEN** 一份口径定义声明了某个标记，但未给出可求值的触发条件
- **THEN** 该定义被判定为不合规

#### Scenario: 触发条件命中时必须携带标记

- **WHEN** 某个标记的触发条件对当前数据求值为真
- **THEN** 该次回答的输出 MUST 携带该标记

### Requirement: 准则依据必须带版本且跨版本比较必须被标记

`standard_basis` MUST 为结构化条目，每条包含准则名称、可定位的条号与版本标识。当同一指标在两个不同准则版本下的结果被比较时，系统 MUST 标记该比较为跨版本。

#### Scenario: 准则依据缺少版本

- **WHEN** 一份口径定义的 `standard_basis` 只有准则名称与条号，没有版本标识
- **THEN** 该定义被判定为不合规

#### Scenario: 跨版本比较

- **WHEN** 比较同一指标在两个报告期的取值，且两期所适用的准则版本不同
- **THEN** 结果 MUST 携带跨版本标记，且该标记出现在证据链中

### Requirement: 引用字段必须声明取值域与缺失表示

对每个被引用的字段，定义 MUST 声明其「缺失」如何表达。对枚举型字段，定义 MUST 声明其合法取值集合。

#### Scenario: 枚举字段缺少取值域

- **WHEN** 一份口径定义的触发条件依赖某枚举字段的取值，但未声明该字段的合法取值集合
- **THEN** 该定义被判定为不合规

#### Scenario: 缺失与零必须可区分

- **WHEN** 某字段在数据源中缺失，且该字段的合法取值包含零
- **THEN** 系统区分「缺失」与「取值为零」，二者走不同分支

### Requirement: 未定义条件必须可机械求值且命中时拒答

一份口径定义 MUST 声明其 `undefined_conditions`，每个条件 MUST 可对给定数据求值。任一条件求值为真时，系统 MUST 拒绝作答并给出可机读的拒答理由。

#### Scenario: 零分母

- **WHEN** 某比率型指标的分母求值为零或负数，且该情况已列入未定义条件
- **THEN** 系统拒绝作答，不返回零、无穷或绝对值

#### Scenario: 拒答理由可机读

- **WHEN** 系统因命中未定义条件而拒答
- **THEN** 拒答理由标识出具体是哪一条未定义条件被命中

#### Scenario: 未定义条件不可求值

- **WHEN** 一份口径定义的某条未定义条件表述为自然语言且无法对数据求值
- **THEN** 该定义被判定为不合规

### Requirement: 常见陷阱必须可执行或显式标注为仅供参考

`common_pitfalls` 中的每一条 MUST 满足以下二者之一：对应到一条可求值的规则（标记触发条件、未定义条件或字段约束），或被显式标注为仅供参考。未标注且无对应规则的陷阱条目 MUST 使定义判定为不合规。

#### Scenario: 陷阱既无规则也无标注

- **WHEN** 一份口径定义的某条 `common_pitfalls` 要求「必须标记某状态」，但定义中不存在对应的标记与触发条件，且该条未被标注为仅供参考
- **THEN** 该定义被判定为不合规

#### Scenario: 显式标注为仅供参考

- **WHEN** 一条陷阱描述的是业务背景而非可判定约束，且已被标注为仅供参考
- **THEN** 该定义在这一条上合规，且该条不参与任何机械校验

### Requirement: 口径版本变更后跨版本结论不可比较

口径定义的版本号变更即视为口径变更。系统 MUST 拒绝把不同版本口径下产出的结论作为同一口径的时间序列进行比较。

#### Scenario: 跨版本时间序列

- **WHEN** 请求比较同一指标在两个报告期的取值，而两期所用的口径定义版本不同
- **THEN** 系统拒绝直接比较，并说明版本差异

#### Scenario: 证据链携带口径版本

- **WHEN** 系统产出任何一条基于口径定义的结论
- **THEN** 证据链中包含所用口径定义的 `metric_id` 与版本号
