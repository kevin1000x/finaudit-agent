## D. 本轮讨论新增（尚未进任何计划）

### D-1 — 是否现在接 LLM API
- **归属**：操作者
- **背景**：操作者指出「没接模型肯定没输出，这个确认意义是什么」——成立
- **agent 判断**：**先冻结、紧接着就接**。理由不是仪式，是**顺序**：
  冻结花两分钟；一旦跑过一次真实模型，「答案先于结果」这个属性就永久不可恢复。
  两个动作的顺序有一个严格更优解，选它不花任何代价
- **判据**：`FREEZE.md` 落地后，Phase 2 的第一个动作就是接 API 并跑 frozen-01 全量

### D-2 — 交付形态：Web 前端 / 本地 GUI / TUI / harness
- **归属**：操作者。已定：**Web 前端要做**（在 `cninfo-analyzer-web` 上增量加页面）
- **已定（2026-08-15）**：Web 精修 + 本地 GUI **也做但减量**，自用适配为主
- **agent 原本反对做两个界面，读了 deepseek-harness 之后撤回一半**：
  它的 `web` / `headless` 两个 profile 共用 `dsh-base`——**同一内核两种壳**。
  若本项目照此分层（语义层 + 执行层 + 证据链为内核，Web 与 GUI 各是薄壳），
  第二个界面的增量成本远小于做两遍。**前提是先把内核与壳切干净**，否则就是做两遍。
- **判据**：ROADMAP Phase 2/4 改写；内核与壳的边界在 ARCHITECTURE.md 里画出来

### D-2b — harness 已澄清并读完
- **指的是** deepseek-ai/deepseek-harness（2026-08-13 开源，TS/MIT，110k star）
- **已沉淀**：`references/deepseek-harness.md`
- **最有价值的发现**：`agent/pre-step` 可 **reject**、`tools/pre-execute` 是**瀑布**
  （listener 不调 `next()` 即阻断）。这正是「语义层闸门不可绕过」需要的形状——
  闸门是**前置钩子**不是**可选工具**，结构上无法绕过；且被 reject 的 turn
  仍入 durable 日志，天然满足 D-003「拒答是第一类产物」
- **判据**：Phase 2 用可拒绝的前置钩子实现口径闸门，不用「可选工具」

### D-3 — PDF 的存储与处理位置
- **归属**：operator 关切，agent 已给方案
- ⚠️ **前一版此处结论是错的，已更正**：我写过「cninfo 没有用 HuggingFace（全仓 grep 无匹配）」。
  实际上后端跑在哪**仓库里根本不写**——生产链路是 Pages Function → 具名 Cloudflare Tunnel
  → `API_BASE`（Pages secret）→ FastAPI。操作者说后端部在 HF Space 上完全成立。
  **这是同一天第三次用「代码里没有」断言「实际没有」。** 不再对操作者的系统下这类判断
- **磁盘实测**：一份茅台年报 143 页 = 3.5 MB。100 公司 × 5 年 ≈ 1.75 GB
- **agent 方案**：**抽完就删，不留 PDF。** 下载 → 抽取 → 落库「结构化行 + PDF 的
  SHA-256 + 巨潮源 URL + 页码」→ 删 PDF。证据链要的是**出处**不是字节，
  任何人凭 URL + 哈希可重新取回核对。存 2 GB PDF 对可审计性零贡献
- **判据**：Phase 1.5 的抽取器默认不保留 PDF；`--keep-pdf` 是显式开关
