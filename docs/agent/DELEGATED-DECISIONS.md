## D-1 —— `h2-02` 的复核者不是人，是一次盲审子 agent

**改了什么**：`N-20` 立过「执行者代答无效」，`02-03-PLAN` 限定 3 要求

**为什么**：操作者 2026-09-09 明确取消「第二位复核者」这道门禁，理由是
找不到专业背书、只是图心安。我核了 `VERIFICATION.md:1435`，
**第一轮的复核者就是操作者本人（有财务背景），备注写着「不独立于本项目」** ——
也就是说当初要的是**独立性**而不是专业性，而现有可选项（操作者 / 我 / 同族模型）
没有一个能提供那种独立性。一个永远无法满足的门禁不是门禁。

**但我没有照单全收「自己确认一下就行」**：H2 测的是「**不知道答案的人**
能不能从这一页判对错」，而我知道答案。我去判，读数不含任何信息。
所以拆成两半：

- **机械那一半**（不需要任何判断）：页面里有没有足够的东西把这个数重算一遍。
  写成检查跑，见 `scripts/check_h2_selfcontained.py`。
- **判断那一半**：空白上下文子 agent，**只喂证据页正文**，不给题面标准答案、
  不给仓库、不给本对话。

**这个读数的效力边界（必须连同结论一起转述）**：

1. 判卷者是**语言模型**，不是有财务背景的人。它读得懂中文、能核对算术，

2. 它与被测系统**同族**（都是 Claude），误差相关，不是独立复核。
3. ⇒ 这个读数能说明的是「**页面自足性**」，**不能**说明「专业人士会认可这个答案」。
   `AC-06` 里属于后者的那部分**仍记 `UNVERIFIED`**。

**要退回去改哪里**：`docs/agent/h2-02/`（整个目录）、

## D-3 —— `N-65`（简称 → 六位代码）做了，**刻意不交给模型**

**改了什么**：`FixtureSource.entity_names`（表从数据文件自己来）+
`parse_intent(entity_names=...)` 注入 + `_Sources` 合表 + 证据页印出这一步。

**为什么现在做**：`h2-02` 的 `H2-03` 判 FAIL 就是它——「华鑫科技 2023 年的
资产负债率」该答 0.55，系统回「题面里没有主体」。盲审三人里有两人被那句
措辞误导过。这是 `A-14` 缺陷一剩下的那一半。

**几条我自己定的判据**：

- **不交给模型**。`intent.py` 第一条硬约束是「能确定性解决的不交给模型」，
  简称→代码是一次查表；拿模型做查表等于把确定性映射换成会错的映射。
- **表从数据源自己来，不另立公司名录**。另立一张，它迟早包含我们答不了的公司，
  那时拒答理由会从「没有这家公司的数据」退化成「认不出主体」。
- **代码优先于简称**。代码是唯一标识，简称会重名会变更。
- **分不清就拒答**：只给「华鑫」（华鑫科技/华鑫股份的共同前缀）⇒ 拒答；
  两份数据源对同一简称给不同代码 ⇒ 那个简称整条丢掉。

**产品上的效果**：「贵州茅台 2023 年的毛利水平是多少」现在全线打通
（简称查表 + 说法归一），此前要打「600519」且要用别名表里的原词。

**要退回去改哪里**：`src/agent/intent.py` 的 `if not entities and entity_names` 那一段、
`src/agent/answer.py` 的 `entity_names` / `entity_resolved_by`、
`src/service/api.py` 的 `_Sources.entity_names`、`tests/test_entity_names.py`。


我的注释白纸黑字写着「与 `_match_alias` 同一条规矩」，而那条规矩的核心

**已修**：命中的公司名左边紧挨着汉字 ⇒ 拒答。并在修的过程中又发现自己
**顺序写反了**（先判左边界会误伤「华鑫科技**和**长风制造」，「和」是连词）——

这类最自然的问法，而我拿不出一条能分开「的」与「集团」的判据。
两种错不对称：误拒还能用六位代码绕，误答会让人相信一个错数。

**复核还抓到的、我一并修了的**：
