# finaudit-agent

**财务分析结论的核查入口。** 粘一段财报分析结论进来 —— 券商 AI、问财、雪球，
或者任何一个大模型写的 —— 系统把它拆成可核声明，**逐条判定**，
并对每一条给出可独立复核的证据链：用了哪张表、哪个指标口径（含版本）、
读到的字段取值是多少、年报原文的 SHA-256 是什么。

**在线试**：<https://cninfo-analyzer-web.pages.dev/#/audit>

---

## 它长什么样

输入：

> 贵州茅台 2023 年净利率 50.6%，资产负债率 17.98%，万华化学 2019 年资产负债率 62%，盈利能力持续增强。

输出：

```
我把这段话读成：待核声明        拆出 4 条

⚠️ 1. 贵州茅台 2023 年净利率 50.6%        口径未声明
       我认出的指标名是「净利率」，它不带口径限定。本系统按「归母净利率」
       算出 0.5060074981155426732183636527，与 50.6% 对得上；
       但换一个口径就是另一个数，而这句话没说是哪一个。

✅ 2. 资产负债率 17.98%                    一致
       （主体 600519、期间 2023 年 承自前一句）
       本系统按「资产负债率」算出 0.1798432413917914711797119101。

❌ 3. 万华化学 2019 年资产负债率 62%       不一致
       本系统算出 0.5464707310379166928094614744，这句话说的是 62%。

·  4. 盈利能力持续增强                     不是可核声明
```

每条判定下面还挂着完整证据链：取数出处（合并资产负债表第几页、哪一列）、
公式、口径定义版本、拒答条件、年报 PDF 指纹。

### 五种判定，封闭集

| | |
|---|---|
| **一致** | 可核，且与本系统算出的数一致 |
| **不一致** | 可核，但对不上 |
| **口径未声明** | 你写的名字不带口径限定，系统替你解释了一个 —— 换个口径是另一个数 |
| **核不了** | 数据或指标不在覆盖范围内，或这句话没解析出主体与期间 |
| **不是可核声明** | 「盈利能力持续增强」这类 |

**后两种是正当输出，不是错误。** 覆盖面窄是刻意选的取舍，
换来的是每一个能核的数都有人逐字段核对过。清单之外的公司得到的是一次
说明原因的拒答，**不是一个编出来的数**。

## 覆盖范围

写在最前面，而不是附注最后 —— 和审计报告把范围限定写在开头是同一个本能。

| | |
|---|---|
| 真实年报 | **贵州茅台 600519 · 2023**（29/29 字段逐字段人工核对）<br>**万华化学 600309 · 2019**（25/25） |
| 指标口径 | **20 份**机器可读定义，含公式、取数出处、拒答条件、可比性标记 |
| 合成夹具 | 6 行虚构公司与虚构数值，页面上**永远标成合成**，用来演示行为 |

数据只来自巨潮资讯网公开年报原文。年报 PDF 本身是权威源，
AKShare 只作对照 —— 茅台 2023 的 24 个字段与 AKShare 逐字段比对，
20 项可比全部一致，0 项不一致。

## 为什么是这个形态

通用 Agent 答得出「净利率是多少」，答不出「**这个口径对不对**」。

净利润有三种口径：归母、含少数股东损益、扣非归母。同一家公司同一年，
选错一个，得到的是一个**看起来完全正常的错数**。实测过：两个通用大模型
在同一道题上错得逐字相同 —— 都取了含少数股东损益的净利润，答 0.124
（正解归母 0.112），**而且都没有拒答**。

这个项目把口径固化成机器可读的定义，让系统在口径不明时**拒答或标注**，
而不是替你选一个然后不告诉你。

**核查是问答的超集**：要核「净利率 50.6%」，系统必须先把净利率算出来。
所以只有一个输入框 —— 不带数就是提问，带数就是待核声明，系统自己判，
并把「我把这段话读成什么」印在报告第一行。判错了要能一眼看出来。

## 架构

```
一段文字
   ↓  agent/verify      切分 → 逐条判定（五态封闭集）
   ↓  agent/intent      说法 → 指标 / 主体 / 期间（LLM 唯一的落脚点，且由调用方注入）
   ↓  agent/gate        执行前闸门：定义合规、版本、封闭节点集、命名空间
   ↓  semantic_layer    口径定义、自建封闭算术求值器（不用 eval）
   ↓  extractor         年报 PDF → 带出处的抽取记录 → 勾稽校验
证据链
```

- **LLM 只在 `intent` 一层**，只做「把一个说法归一到一个已存在的指标名」。
  它不产生新指标、不判断口径、不参与计算；模型给出的名字**仍要过别名表**。
  没配模型时整条路径离线跑完。
- **算术不用 `eval()`**，是自建的封闭解析器，节点集封闭。
- **服务端零 Web 框架依赖**，运行时第三方闭包只有 PyYAML 一个。
- 单轮无状态 —— 这是「同一问题两次同一执行哈希」成立的原因。

一页纸详版：[`docs/public/ARCHITECTURE-ONEPAGER.md`](docs/public/ARCHITECTURE-ONEPAGER.md)

## 怎么自己验一遍

```bash
pip install -e .
python -m service.api                      # 监听 8100

curl -X POST localhost:8100/verify \
  -H 'Content-Type: application/json' \
  -d '{"text":"600519 2023 年资产负债率 17.98%"}'
```

复算任何一个数，不需要信这个系统：证据链里有取数出处（哪张表、哪一页、哪一列）
与两个被除数，拿年报原文照着核。

```bash
pytest -q                                  # 测试
python -m semantic_layer validate          # 口径定义合规
python -m eval.run --suite frozen-01       # 问答层评测
python -m eval.verify_run --suite frozen-03  # 核查层评测
```

评测集在看到任何模型输出**之前**冻结，逐文件 SHA-256 存档；
冻结校验不过就拒绝运行评测。读数与方法：
[`docs/public/EVAL-ONEPAGER.md`](docs/public/EVAL-ONEPAGER.md)

## 已知边界

- **覆盖 2 家公司**。这是刻意的取舍，不是待办 —— 见上面「覆盖范围」。
- **准则检索没做。** 名字里的 `audit` 指的是「可审计」（性质），
  不是「审计」（业务领域）；本系统不检索会计准则条文。
- **「证据链能让人在 5 分钟内独立复核」这个假设尚未由外部审计背景人士验证。**
  已做的三轮复核者是模型与作者本人 —— 那能说明页面自足性，不说明专业认可。
- 不收用户上传的财务数据。核查入口只接受一段文字：
  粘进来的结论是**被判定的对象**，任何时候都不当事实用，不落盘。

## 借鉴

这个项目的几处关键机制来自读别人的东西。**笔记本身不在本仓**（26,840 行，
是我自己的学习记录，对读这个项目的人没用），这里只说借到了什么：

- **[DeepSeek 的 agent harness 文档与事故复盘](https://github.com/deepseek-ai)**
  —— 「**一道门只有在真实回归能让它红的时候才算门**」。本项目的第六道门
  （`scripts/check_gates.py`，查我们自己的测试有没有可失败点）和
  `rules/commands.md` 里那条人执行的「造回归 → 看红 → 回退」程序，都出自这里。
  它那份复盘记着一个 178 个单测全绿、100% 行覆盖、而产品完全不可用的案例。
  另外「删除记录必须写下**放弃了什么能力**与**重新引入条件**」这个归档形态也是从那里借的。
- **[hello-agents](https://github.com/datawhalechina/hello-agents)**（Datawhale）
  —— agent 分层与工具边界的对照系。本项目「LLM 只在 `intent` 一层、由调用方注入、
  答案仍要过别名表」这条边界，是拿它的框架章节做参照定下来的。
- **[cninfo-financial-analyzer](https://github.com/kevin1000x/cninfo-financial-analyzer)**
  —— 同一作者的上游项目。年报下载、PDF 版面解析、以及本服务的容器托管都建在它上面；
  本项目的核查端点就挂在它的 `/audit/*` 下。

数据与工具：巨潮资讯网（年报原文）、[AKShare](https://github.com/akfamily/akshare)（仅作对照源）、
[pdfplumber](https://github.com/jsvine/pdfplumber)（PDF 文本与表格）。
